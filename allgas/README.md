# Preventah All Gas

Three prevention actions a day, at three budgets, for a whole household.

Family history is a household fact, so this treats prevention as a household
activity. You consent, you pick the conditions that actually run in your
family, and each day you get three actions drawn from curated public-health
guidance. Every action comes at three spend tiers, and the free tier is always
a real option rather than a locked preview. Checking one off lands on every
other phone in the household immediately.

## The loop

1. **Create or join a household.** Six-character code, no accounts.
2. **Consent.** Nothing about anyone's family health is collected first.
3. **Pick conditions.** Search a curated catalog of 100+ entries. No free text
   ever reaches the database.
4. **Do one of today's three.** Diet, exercise, habit, each at free / cheap /
   premium.
5. **Check in.** The household board updates live.
6. **Morning plan and nudge.** AgentMail sends the day's three at 07:00 local,
   and a gentle nudge at 19:00 if yesterday went by empty.

## Stack

Vite + React on the frontend, Convex for everything else. The deployment
serves its own frontend from `convex/http.ts`, so the app and its API share
one origin on `*.convex.site`.

| Piece | Where |
|---|---|
| Schema, indexes | `convex/schema.ts` |
| Household + live board | `convex/households.ts` |
| Consent, conditions, today's actions | `convex/members.ts` |
| Check-in | `convex/checkins.ts` |
| Condition catalog search | `convex/catalog.ts` |
| Firecrawl source cards | `convex/sources.ts` |
| AgentMail morning plan + nudge | `convex/mail.ts` |
| Crons | `convex/crons.ts` |
| Static site router | `convex/http.ts` |

`convex/lib/` holds the curated data, ported from the main Preventah app:
the condition catalog, the plan content, and the pure resolver that turns a
set of conditions into a day's three actions. It is pure and synchronous, so
opening the app never waits on a model or a network call. `convex/lib/tiers.ts`
is new here: it derives the three spend tiers from a resolved action.

## Running it

```bash
npm install
npx convex dev          # creates the deployment, writes .env.local, generates convex/_generated
npm run dev:frontend    # in a second terminal
```

Then set the two keys on the deployment:

```bash
npx convex env set FIRECRAWL_API_KEY <key>
npx convex env set AGENTMAIL_API_KEY <key>
npx convex env set AGENTMAIL_INBOX_ID <inbox>   # optional
```

Neither key is required to run the loop. Without Firecrawl the source cards
stay empty and say why; without AgentMail the mail tab reports that the key is
missing. The daily loop itself never touches either.

## Deploying

```bash
npm run deploy
```

That builds the SPA, embeds it into `convex/siteAssets.ts`, and pushes
functions plus site to the deployment. The app is then live on the
deployment's `.convex.site` origin.

`convex/siteAssets.ts` is generated by `scripts/embed-site.mjs` and committed
so a fresh clone can deploy in one command. Do not edit it by hand.

## Tests

```bash
npm test
```

Covers the pure core: a plan resolves for any input including nonsense, the
same selections and day always give the same plan, every action offers all
three tiers, and the condition sanitizer drops anything that is not a catalog
id.

## What this is not

General lifestyle guidance from public-health sources. Not medical advice, not
a diagnosis, not a prediction. A family history raises the value of prevention
and of a conversation with a clinician; it does not mean anyone will develop a
condition.

The join code is a convenience, not an access control boundary, and the UI
says so.
